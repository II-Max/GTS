## 2024-05-18 - [Optimize public_leaderboard query to prevent O(N) payload bottleneck]
**Learning:** In a Firebase Realtime Database architecture without explicit query limits, frontend features like the leaderboard (`rank.html`) would download the entire `public_leaderboard` object. This causes an O(N) bandwidth bottleneck as the platform scales. Furthermore, since RTDB doesn't natively support compound sorting on multiple fields, extracting ordered elements correctly requires `snap.forEach()` to retain primary indexed sorting and secondary client-side sorting for tie-breakers.
**Action:** Always add explicit `.indexOn` rules to `database.rules.json` for fields used in queries. For large collections, use `orderByChild(...).limitToLast(N)` in queries to restrict payload sizes, and avoid `Object.entries(snap.val())` which strips the RTDB response order. Instead, use `snap.forEach()`.
