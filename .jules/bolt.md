## 2025-02-27 - Firebase Query Optimization with Tie-Breakers
**Learning:** Firebase Realtime Database does not natively support querying or sorting by multiple keys simultaneously via the REST API or SDK. Also, relying strictly on retrieving full payload structures like `db.ref('public_leaderboard').once('value')` for ranked displays forces an O(N) client-side download bottleneck.
**Action:** Always set an `.indexOn` rule for the primary sorting field in `database.rules.json` (e.g., `score`), query via `.orderByChild('score').limitToLast(LIMIT)`, and use `snap.forEach()` to preserve the returned order. Because Firebase cannot handle multiple sort fields natively, fallback to a secondary client-side sort for tie-breakers. This ensures an exact functional match with O(1) payload fetching.
