## 2024-05-18 - Avoid O(N) memory / network full collection downloads for leaderboard
**Learning:** In a codebase using Firebase Realtime Database for leaderboard tracking, calling `db.ref('public_leaderboard').once('value')` on the frontend or `db.reference("users").get()` on the backend will download the ENTIRE table into memory to sort it client/server side. This is extremely inefficient and causes memory leaks and huge network payloads when users scale.
**Action:** Add Firebase Realtime Database `.indexOn: ["score"]` rule on the necessary node, and query using `.orderByChild('score').limitToLast(50)` (frontend) or `.order_by_child("score").limit_to_last(limit).get()` (backend) to rely on Firebase server-side sorting, reducing the payload strictly to only the items needed for UI rendering.
