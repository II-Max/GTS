## 2024-10-18 - Firebase RTDB Top-N Queries Optimization
**Learning:** In Firebase Realtime Database, fetching an entire node (like a leaderboard with all users) just to sort and display the top N results in the frontend leads to a severe O(N) bandwidth bottleneck. It downloads all users instead of just the top 50, which causes significant load time degradation and wastes network bandwidth as the user base grows.
**Action:** Always combine `.indexOn` rules on the server side with `orderByChild().limitToLast(N)` client queries for top-N lists. Then, iterate the results using `snap.forEach()` (to safely preserve order) instead of converting `snap.val()` to an object array. If tie-breaking with secondary sorting is needed, it must be performed client-side using `Array.prototype.sort()` because RTDB native queries only support sorting by a single key.
